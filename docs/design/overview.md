# offsave 設計メモ(決定事項)

友達同士で互いのスクリーンタイムを管理するツール。Windows / Linux / Android 対応。
Tailscale(ノード共有)の上でだけ動き、[disnans](https://github.com/3pino/disnans) と同じ土台を使う。

状態の凡例: **決定** / **仮置き**(解釈を置いたもの。違えば直す) / **未決**

## 1. 前提と方針

- **決定**: 相互監視。参加者全員が合意の上で使う。隠しモードは作らない(常駐表示・初回の同意あり)。
- **決定**: 回避の「防止」は程々にし、「検知と通知」を優先する。
- **決定**: 制限の強制は必ず端末ローカルで行う。サーバー(や Tailscale)につながらないときは、最後に受け取ったルールで制限を続ける。
- **決定**: 友達の許可が原則。ただし本人が手順を踏めば一時解除できる(友達に通知)。
- **決定**: 友達は 1 人の承認で足りる(複数人の合意は不要)。
- **決定**: サーバー管理者は全データを見られる。相互監視の前提で信頼する(README に明記)。
- **未決**: ライセンス。大っぴらには公開しない。公開する前に決める。

## 2. 構成

- disnans と同じ系統の構成: `crates/{core,server}` + Tauri(Svelte)+ axum + SQLite。`core` は判定ロジックとサーバーとの型。デスクトップのエージェントを作るときに、クライアント用のクレートを足す。
- 認証は Tailscale の whois(disnans と同じ)。ノード共有で友達を招待し、ACL に offsave のポートを追加する。
- disnans とは別アプリ・別サーバープロセス(同じ PC の別ポート)。disnans 側で共通化されている部品は再利用を検討する。
- Rust の共通コア(ルール評価・集計・同期・オフライン動作)と、OS ごとの部品に分ける。
  - Android: Kotlin(Accessibility Service・Device Admin・UsageStats)。Tauri から呼ぶ。
  - Windows: サービス(監視・ハートビート・ヘルパーの再起動)+ ユーザーセッション内のヘルパー(前面ウィンドウ取得・オーバーレイ)。
  - Linux: systemd サービス。KDE Wayland は KWin スクリプト + D-Bus。
- ダッシュボードはアプリ内(Tauri)。

## 3. ルール

- ルールは「対象のまとまり」+「制限(複数)」で作る。カテゴリ機能は作らない。
  - 対象のまとまり(グループ): アプリとドメインを自由に混ぜられる。例: `gamea` + `gameb` + `game.com` の合計 n 時間。
  - **決定**: 1 つのルールに制限を複数置ける。どれか 1 つでも当たっていれば使えない。例: 「合計 1 時間」+「毎日 6:00–7:00 は禁止」+「平日は 15:00–23:00 も禁止」。
  - 制限の種類(どちらも曜日を指定できる):
    - 時間帯(いつからいつまで。日をまたぐ指定も可。曜日は「始まる日」)
    - 1 日の合計時間(曜日は「論理日の曜日」。平日 3 時間・休日 1 時間、のように分けられる)
  - 猶予は、制限ごとに 1 回(同じルールでも、合計と時間帯は別の「制限到達イベント」)。
- 制限は、ユーザー単位で全登録デバイスを横断して合計する。
  - **決定**: 同時に複数デバイスを使っていても、重複を除いた実時間で数える(区間の和集合)。
  - **決定**: 数えるのは前面にある時間だけ。画面オフとアイドル 5 分で停止する。
- アプリの同一視は「正規アプリ」の表で行う(OS ごとの識別子を対応させる)。
  - Android: パッケージ名 / Windows: exe 名 / Linux: desktop ファイルか WM_CLASS。
- **決定**: 日付の境界は午前 4 時(デフォルト)。タイムゾーンは端末ではなくユーザー単位でサーバーが保持する。
- **決定**: 友達は、日付指定のオーバーライド(例: 「明日は制限なし」)とルール本体の編集ができる。
- **決定**: 本人が自分のルールを厳しくするのは、即時に反映してよい。
- **決定**: オフライン時のほかデバイスの利用分は、最後に同期した値を使う。
- **決定**: 時計の改ざん対策として、サーバー時刻との差分を保持する。オフライン中に時計が大きく動いたら、再接続まで日付をリセットしない。

### 制限に達したとき

1. 制限に達したら、1 分だけ追加で使える(猶予)。
2. その後はオーバーレイでブロックする。
3. 猶予は「制限到達イベント」ごとに 1 回ずつ。**仮置き**: 同じ時間帯や同じ日のうちにアプリを開き直しても、猶予は再付与しない。一時解除が終わって再び制限に達したときは、新しいイベントとして再び猶予を与える。

### 本人による一時解除(「面倒な手順」)

1. ブロック画面から「一時解除」を選ぶ。
2. 解除が必要な理由をタイプする。この文章が、友達に送る通知の本文になる。
3. 確認ポップアップを出す。「本当にこの解除があなたに必要ですか?」「友達に通知が行きますが、よいですか?」。毎回 10 秒の考える時間を置き、その間は決定ボタンを押せない。
4. 決定すると解除され、友達に通知が行く。ログにも残る。
- **決定**: 解除の長さは 15 分。解除は、そのユーザーの全デバイス・全ルールに効く。
- **仮置き**: 1 日の回数上限は付けない(友達への通知が歯止め)。

### 利用の表示

- 「今日の利用」には、アプリのアイコンと、サイトのファビアイコンを出す。
  - **決定**: アプリのアイコンは、デバイスが「初めて使ったアプリ」の分だけ小さな PNG（16KB まで）を WebSocket で送り、サーバーが保存する（友達の画面でも出せる）。同じアプリは 7 日間更新しない。
  - **決定**: サイトのファビアイコンは、画面ではなく**サーバーが取る**（友達が見たサイトに、見ている人の接続元が知られないため）。`https` と標準ポートだけ、IP アドレスや `.local` は取らない、名前を引いたアドレスが公開されていないもの（Tailscale のアドレスを含む）なら取らない、引いたアドレスに接続を固定する、リダイレクトは行き先も同じ確認をして 3 回まで、画像は先頭のバイト列で確かめる（SVG は受けない）、1 つ 128KB まで。`/favicon.ico` が無いときは、ページの `<link rel="icon">` を探す。取れたものは 7 日、取れなかったものは 1 日キャッシュする。
- **決定**: 「今日の利用」は、初めは 1 分以下のものと、設定の「非表示のアプリ」に入れたものを隠す。「続きを表示」で、いつでも全部見られる。表示だけの設定（記録・制限には影響しない）で、このデバイスの画面だけに効く。既定の非表示は無し。
- **決定**: 友達の申請は、offsave を使っている人の一覧（友達でも申請中でもない人）から、名前で絞り込んで選ぶ。Tailscale のノード一覧は見ない（offsave を開いていない人は、どうせ友達にできないため）。

## 4. Web 制限

- **決定**: DNS 方式は使わない(ノード共有ではサーバー側から DNS を配れない。Android の VPN は Tailscale が使っている)。
- **決定**: URL は、読んだ時点でホスト名だけにする。パス・クエリ・フラグメントは、保存も送信もしない(トークンが載りうるため)。
- Windows / Linux: ブラウザ拡張で URL を取り、ブロックする(**未実装**)。
  - 拡張はローカルのエージェントと Native Messaging で通信する(サーバーへは直接送らない)。
- Android(**実装済み**): ブラウザが前面にある間だけ、2 秒おきに Accessibility で URL バーを読み、ホスト名を `domain:<host>` の利用区間として、アプリの区間と並行して記録する。入力中の URL バーは読まない。全画面動画などでバーが見えない間は、直前のサイトを続ける。
  - 対応ブラウザ: Chrome と Firefox 161（どちらもエミュレーターで確認済み）、Chrome Beta/Dev/Canary・Brave・Edge・Vivaldi・Samsung Internet・Firefox の派生（Beta・Nightly・Fennec F-Droid・Iceraven・Mull。同じ系統の ID で書いたが、実機での確認が要る）。
  - Firefox の新しいツールバー（Compose）は、URL を `text` でなく説明文（`" example.com. Search or enter address"`）で返し、ノードは view ID では見つからない。外側の View（`composable_toolbar`）を ID で見つけ、その中を数を限ってたどって、`ADDRESSBAR_URL_BOX` のノードの説明文の先頭から読む。古い View 版のツールバー（`mozac_browser_toolbar_url_view`）も読む。
- **決定**: 対応ブラウザは許可リスト化する。リスト外のブラウザの起動は、友達に通知する(**実装済み**: 同じブラウザは 1 時間に 1 回。ブロックはしない)。
- **決定**: Windows / Linux では、ブラウザのポリシー(拡張の強制インストール・DoH 無効化)をインストール時に設定する。
- **決定**: シークレットモードは、まず後回しにする。いずれは拡張の許可を必須にする。
- **決定**: 制限に達したときは、どのサイト・アプリかを添えて友達に通知する(**実装済み**: 制限到達のイベントごとに 1 回)。
- ドメイン単位の制限をまず作る(パス単位は後)。

## 5. 検知と通知

- ハートビートは、サーバーへの WebSocket に 60 秒ごとに送るメッセージ(保護の状態・前面のもの・未送信の利用区間を載せ、返事で方針を受け取る)。友達への即時通知も同じ経路で受ける。
  - Android: foreground service(disnans と同じやり方)。
  - **要検証**: 画面オフの深い Doze の間は、電池の最適化から除外していても、タイマーが止まって途絶えることがある。実機で、夜間の途絶の誤通知がどのくらい出るかを測る。
- 端末の時計は、サーバーの時刻を基準に、経過時間(elapsedRealtime)で進める(**実装済み**)。端末の時計を動かしても、日付や制限は動かない。3 分以上ずれていたら、友達に通知する。
- 判定はサーバー側。**決定**: 最後の連絡から 10 分たっても次が来ないとき（ハートビートは 60 秒ごとなので、約 10 回分）、「疑い」として友達に通知する。画面を消している間に通信が止まることはよくあるため（当初は 3 分）。`OFFSAVE_SUSPECT_AFTER_SECS` で変えられる。
- ハートビートに状態フラグを載せる(Accessibility 有効か、Device Admin 有効か、など)。コールバックが届かなくても無効化を検知できる。
- 端末は正常シャットダウン時に、その旨を送ってから落ちる(電源オフとの区別)。
- アンインストール、無効化、Tailscale 切断は、すべて「ハートビート途絶」として検知する。
- Android の追加対策:
  - Device Admin でアンインストールを難しくし、解除時にコールバックで通知する。
  - Accessibility で、設定のアプリ情報・Accessibility 設定・アンインストール画面への遷移を検知し、ブロックか通知を行う。
  - Android 13 以降は、サイドロードの「制限された設定」を許可する手順をオンボーディングで案内する。
  - Device Owner は使わない。配布は APK。
- **決定**: デバイスの削除は、本人にも友達にもできる(どちらも友達に通知し、友達による削除は、だれが消したかを本文に入れる)。削除されたデバイスは、最後に受け取ったルールで制限を続けるが、新しいルールは届かない(アプリには、登録が外れた旨を出す)。
- 端末の追加と削除は、友達に通知する(承認は不要)。**仮置き**: 登録していない端末の利用は計測できないが、登録済みの端末を横断した合計時間で制限できればよい、として割り切る。

## 6. 関係の解消

- どちらからでも一方的に解消できる。**決定**: 即時。ただし「本当に解消しますか?」の確認を入れる。
- 解消すると相手に通知が行き、その相手由来のルールは消える。履歴は残す。

## 7. 既知の限界(検知も通知もできないもの)

「ハートビート途絶」「状態フラグ」「Accessibility のイベント」「端末の登録・削除通知」のいずれでも検知できないものだけを挙げる。

- Android: 別プロファイル(Work profile・Private Space・アプリのクローン機能・サブユーザー)の中での利用内容。プロファイルの存在確認は試みる(要検証)。
- 全 OS: 未登録の端末での利用。
- Windows / Linux: 別の OS を起動した利用や VM 内の利用。ホストが動いていれば、起動の事実は残る。
- Windows / Linux: 管理者権限を持つ本人による、エージェントを止めない形の改変(止めればハートビート途絶で検知される)。

## 8. 開発順(MVP)

1. サーバー + Android(Accessibility で前面アプリ取得 → 時間制限 → オーバーレイ + ハートビート): **実装済み**。サイトの制限(Chrome 系)も含む。
2. Windows の同機能: 未実装
3. デスクトップのブラウザ拡張による URL 取得と制限: 未実装
4. Linux(まずブラウザだけ。アプリ制限は KDE Wayland で後から): 未実装

### 実機で確認が要る点

- Chrome・Firefox 以外のブラウザの URL バーの ID。
- Doze の間のハートビート。
- 「設定画面の見張り」(offsave のアンインストール・無効化の画面を開いたらホームに戻す)の文言の判定。端末の言語・Android の版で画面の文言が違う。
- Device Admin が有効な間のアンインストールの手順。
